## 5. Efforts

| Effort | HR (bpm) | Pace at 3:30 fitness | Feel | Used for |
|---|---|---|---|---|
| Recovery | < 143 | 6:14–6:29 | very easy | day after hard sessions |
| **Easy / long** | 143–157 | 5:39–6:14 | conversational | ~80% of km, long runs |
| Marathon pace (MP) | 158–170 | 4:54–5:04 | steady, short sentences | MP runs, MP finishes |
| **Threshold / tempo** | 171–179 | 4:33–4:41 | comfortably hard (~1 h race effort) | tempo, cruise intervals |
| Intervals (VO₂) | 180–190 | 4:09–4:19 | 5–10 km race effort | 800 m–4′ repeats |

- HR = % of heart-rate reserve (Karvonen) on rest 46 / max 195. Until the tests, **run easy days by HR,
  not pace**. Paces are the targets at goal fitness.
- **Intervals: run by effort**, HR lags on short repeats. After the 5 km test, interval pace ≈ 5 km time ÷ 5.
- **Bike / swim: easy only**, RPE 3–4 of 10. On the bike HR sits ~5–10 bpm lower than running.
- Update this table after each test: new threshold HR (30′ test) → move the zones.

## 7. Weekly check-in (once a week)

**When:** Sunday evening, after the long run (or Monday morning).

**Tommaso sends** (copy this):

```
Weekly check-in · week of <Monday date>
Next week I can train: Mon __ Tue __ Wed __ Thu __ Fri __ Sat __ Sun __ (✓ / ✗ / only evening)
How I feel (1–10): __   Sleep: __   Stress: __
Pain / niggles: __
Anything special (travel, exams, events): __
```

**You do, in this order:**

1. **Read the data** (section 8): last 7 days of activities, feedback (RPE, feeling, notes), check-ins,
   open flags, this week's and next week's targets.
2. **Review last week** in 5 lines max: done vs target (km, runs, long run, quality, gym, bike), how the
   key session went (pace vs HR), anything to watch (ACWR, soreness, sleep).
3. **Decide next week** within the season's targets for that week:
   - ≥ 90% of last week's target done → follow the plan.
   - 70–90% → follow the plan but drop the extra volume, keep the key session.
   - < 70%, illness, or a pain flag → **propose** a lighter repeat week instead of cramming (season change).
   - Pain: no running on it; easy bike only if pain-free; tell Tommaso to see a physio if it lasts > 3 days.
4. **Write next week day by day** on the days Tommaso is free: session, distance/duration, **effort (HR
   zone)**, and for gym which template (A/B/C). Long run on the day with most time. Hard days (quality,
   long run, heavy gym) never back to back; 48 h between full-body gym sessions.
5. **Put the sessions in the app as proposals** (section 9) so Tommaso approves them on the Week View.
6. If the **season** itself should change (targets, blocks, races), propose it (section 9) and say why.

**Output format:**

```
Last week: <done> / <target> km · <runs> runs · long <x> km · gym <n> · bike <n>  → <one-line verdict>
Watch: <one line or "nothing">
Next week (<block>, week x/y, target <km> km):
Mon  <session> · <km or min> · <effort / HR> 
...
Sun  <session> ...
Changes proposed: <none | what + why>
```

## 8. Reading the data (Supabase connector)

The app's database is Supabase project **`cvfdficzypuxkumyimwd`**. If this Cowork project has the
**Supabase** connector, use `execute_sql` (read-only queries unless section 9 applies). Check access
with: `select count(*) from activities;`. If you have no access, ask Tommaso for the week's Garmin
summary instead.

```sql
-- Last 7 days (runs, gym, HIIT, bike/swim) with feedback
select date, type, sport_type, name, distance_km, duration_min, avg_pace, avg_hr, max_hr,
       rpe, feeling_score, feedback_notes
from activities where date >= current_date - 7 order by date;

-- Check-ins and open flags
select date, feeling_score, sleep_hours, soreness, stress, notes from checkins
where date >= current_date - 14 order by date;
select date, type, description from flags where not resolved order by date;

-- This and next week's targets (approved season)
select w.week_start, m.name as block, w.is_deload, w.run_km, w.long_run_km, w.runs,
       w.quality_sessions, w.gym_sessions, w.cross_sessions, w.key_session, w.milestone
from season_weeks w join mesocycles m on m.id = w.mesocycle_id join seasons s on s.id = w.season_id
where s.status = 'approved' and w.week_start between date_trunc('week', current_date)::date - 7
                                                 and date_trunc('week', current_date)::date + 7
order by w.week_start;

-- Load by type (AU), planned load and the 80/20 split (computed by the app; read, don't recompute)
select week_start, run, gym, hiit, cross_training, total, estimated_share from weekly_load
where week_start >= date_trunc('week', current_date)::date - 35 order by week_start;
select week_start, planned, planned_source from season_week_load
where season_status = 'approved' and week_start between date_trunc('week', current_date)::date - 7
                                                     and date_trunc('week', current_date)::date + 7;
select week_start, band_easy_min, band_moderate_min, band_hard_min, easy_share, missing from weekly_zones
where week_start >= date_trunc('week', current_date)::date - 21 order by week_start;

-- What is already planned for next week
select day, session_type, target_distance_km, status, notes from weekly_plans
where week_start_date = date_trunc('week', current_date)::date + 7 order by day;
```

(`seasons`, `mesocycles`, `season_weeks` are live since 5 Oct 2026; the load and zone views since step L. The approved season is the source of truth; section 4 is the version Tommaso reviewed.)
